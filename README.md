# 短剧广告跳过助手（AutoSkip）

一个纯本地运行的 Android 无障碍工具：在红果短剧、抖音、快手等应用里检测广告，倒计时结束点「跳过」，
遇到没有跳过按钮的**商城 / 直播推广广告**则点「不感兴趣」或上滑。

- 包名：`com.autoskip.ad`
- 版本：1.2（versionCode 3）
- 最低系统：Android 8.0（API 26），targetSdk 34
- 权限：只需要「无障碍服务」，**不联网、不申请网络权限、不上传任何数据**

---

## 1. 安装

```
adb install -r dist/AutoSkip-v1.2.apk
```

或用手机打开 APK 安装（需允许「安装未知来源应用」）。可直接覆盖安装 1.0 / 1.1，配置会保留。

## 2. 首次使用

1. 打开 App → 点右上角「去开启」→ 系统设置里找到 **短剧广告跳过助手** → 打开开关。
2. 回到 App，状态卡片变成绿色「已开启，正在后台守候」。
3. 默认已勾选红果短剧、抖音、抖音极速版、快手、快手极速版、番茄小说、番茄畅听；
   其他应用可在「生效应用」里自己加。
4. 去短剧 App 里正常看剧即可。

> 建议先用「演练模式」跑一集：它只写日志不动手，日志里能看到 `读秒中 5s`、`倒计时结束…点击…`、
> `识别到直播/商城推广广告，自动上滑跳过` 就说明识别到了；看不到就按第 6 节抓一次界面。

## 3. 四种模式

| 模式 | 行为 |
|---|---|
| 智能（推荐） | 有「跳过/关闭广告」按钮就点；遇到商城/直播推广广告点「不感兴趣」或上滑 |
| 只上滑 | 倒计时结束、遇到推广广告时直接滑走 |
| 只点跳过 | 只点按钮（含「不感兴趣」），不改变视频进度 |
| 演练模式 | 只在日志里显示识别结果，不执行动作 |

其他可调项：

- **结束后延迟**（0–1500ms）：倒计时消失后等多久再动作。
- **每次上滑次数**（1–3）。
- **动作时轻微震动**。
- **记录每次扫描**：把每一帧的识别细节写进日志。
- **没按钮时自动上滑**（默认关闭）：倒计时结束后一个按钮都没有时直接滑走。
  红果这类 App 的剧情会自动续播，此时上滑容易直接滑掉一整集，所以默认不开。
- **识别商城/直播推广广告**（默认开启）：见第 5 节。
- **读不到界面时定时上滑**（默认关闭）：极端兜底，见第 6 节。

## 4. 识别原理

不截图、不做图像识别，只读无障碍节点树上的文字、id 和位置，按可靠性排序：

1. **viewId 命中**：`tt_splash_skip_btn`、`ad_skip`、`close_ad` 这类广告 SDK 固定 id，几乎不会误判。
2. **按钮自带倒计时**：`跳过 5` → `跳过 4` → … → `跳过`。
3. **独立读秒**：`5秒`、`12s`。必须**观察到数值递减**才算倒计时，避免把静态的 `30秒` 时长标签当倒计时。
4. **只有数字的角落计时器**：位置固定且逐帧 `-1` 才算。
5. **无文字的自绘按钮**：广告 SDK 常用一个没有 text/desc 的 View 当跳过按钮，
   只在「读秒刚结束 3 秒内 + 屏幕右上角 + 按钮尺寸」时才点，风险可控。
6. **商城 / 直播推广广告**（1.2 新增，见第 5 节）。
7. **「上滑继续」**：必须**已有广告上下文**才滑。红果的剧集播放页底部**常驻**「上滑继续看短剧」，
   无条件上滑会把正常追剧一路滑掉。
8. **兜底盲滑**：界面完全读不到时的定时上滑，默认关闭。

「广告/赞助」只作为场景辅助证据，不单独触发。`跳过片头`、`跳过片尾`、`下一集`、`取消`、`开通会员`
这类文字被显式排除，绝不会被当成广告跳过。

判定结束：读秒持续 ≥0.3 秒（或至少两帧）→ 数字消失 ≥0.34 秒 → 且距离上次动作超过冷却时间。

## 5. 商城 / 直播推广广告（1.2 的核心新增）

红果的中插广告有很大一类**根本没有「跳过」按钮**，实测遇到两种典型界面：

| 形态 | 界面特征 |
|---|---|
| 直播间带货 | 全屏直播画面 + `直播中` + `点击进入直播间` + 底部 `上滑继续看短剧` |
| 商城推广 | 底部弹「商城好物省心选」卡片 + `去商城购买` + `不感兴趣` + 底部 `上滑继续看短剧` |

这两种界面里一个「跳过」字样都没有，1.1 及以前一动不动。

1.2 的做法：

- **强标志**（命中一个就判定）：`去商城购买`、`立即购买`、`加入购物车`、`不感兴趣`、
  `点击进入直播间`、`进入直播间`、`商城好物`、`红果优选`、`小黄车` 等。
- **弱标志**（同一屏命中 ≥2 个不同词才判定）：`直播中`、`讲解中`、`已售`、`旗舰店`、
  `优惠券`、`消费券`、`包邮`、`秒杀`、`图集`、`商城`、`好物` 等。
- 特征需连续存在 0.6 秒才动作，避免一闪而过的推荐卡片被误点。
- **优先点「不感兴趣」**（直接关掉推广层，最安全），没有才上滑。
- 连续 3 次上滑都没滑走 → 暂停 12 秒再试，避免对着滑不动的浮层狂滑。

## 6. 卡住了怎么排查

1. 打开「记录每次扫描」，去广告里待 10 秒，回来看日志：
   - 有 `扫描 N 节点` 但一直是「无动作」→ 规则没命中，把日志 + 抓取的节点树发出来；
   - 一条 `扫描` 都没有 → 服务没在跑，检查无障碍开关 / 电池策略。
2. 播到广告时让它停留 3~5 秒，然后切回本应用点「抓取当前界面」→「复制」。

   1.2 的诊断会带回**最近 8 帧（约 6 秒）每一帧的节点列表**，再加上**当前界面（含不可见节点）**，
   够你在切回来的路上不丢现场。三种情况一眼能分开：

   | 诊断里看到 | 结论 | 对策 |
   |---|---|---|
   | 广告帧里能看到 `跳过`、`5s`、`tt_splash_skip_btn` | 无障碍正常，规则问题 | 把内容发出来补规则 |
   | 广告帧里能看到 `直播中`/`商城好物`，但没动作 | 命中推广规则前就被打断了 | 看日志里的 reason |
   | 广告帧「节点 0~3 个」或全是 `不可见` | 广告容器对无障碍隐藏了 | 打开「读不到界面时定时上滑」 |

3. 日志里出现 `上滑未执行：手势被拒绝` → 系统把 `dispatchGesture` 拦了，通常是厂商的「无障碍增强保护」，
   需要在设置里给本应用放行。

### 关于「读不到界面时定时上滑」

红果有一部分广告是 WebView / 自绘层，整棵子树被设成对无障碍不可见，此时**任何文字规则都失效**。
这个开关会在「当前只读到 ≤15 个节点」时，每 5 秒上滑一次。

它**无法区分广告和正常播放**（如果某个 App 正常播放时也读不到界面，就会误滑），所以默认关闭，
并且同时受「处理方式」限制：只在智能 / 只上滑模式下生效。

## 7. 1.2 修了什么

| # | 1.1 的问题 | 后果 | 1.2 的做法 |
|---|---|---|---|
| 1 | 完全不认识「商城 / 直播间」类广告 | 这两种界面没有跳过按钮，一动不动 | 新增强/弱标志双层识别，点「不感兴趣」或上滑 |
| 2 | 「上滑继续」只要出现就滑 | 红果播放页底部常驻该提示，正常追剧会被一路滑掉 | 必须有广告上下文才滑，且推广场景优先走点按钮 |
| 3 | 诊断只留「最近一次广告画面」，且只在读秒时留 | 推广广告没有读秒 → 永远没快照 → 「抓取不到」 | 改成最近 8 帧滚动缓冲（约 6 秒），不再依赖读秒 |
| 4 | 诊断只看 `isVisibleToUser()==true` 的节点 | 广告被标成不可见时，诊断里也“什么都没有” | 诊断模式把不可见节点一并导出并标注 |
| 5 | 上滑轨迹固定、无复查 | 每次同样轨迹易被判脚本；滑没滑走不知道 | 起点/终点加随机偏移、中间补点；滑完 700ms 主动复查 |
| 6 | 界面读不到时无任何手段 | 技术上限处直接躺平 | 新增可选兜底上滑（默认关） |

## 8. 1.1 修了什么（1.0 在真机上不生效的原因）

| # | 1.0 的问题 | 后果 | 1.1 的做法 |
|---|---|---|---|
| 1 | 只靠无障碍事件触发扫描 | 广告期画面只有视频帧在动，几秒都没有事件，整段广告扫不到 | 加 200ms 心跳轮询，广告结束后 6 秒内保持高频 |
| 2 | 判定「结束」要求首帧到末帧读秒 ≥900ms | 只抓到一帧读秒时永远不成立 | 改为「持续 ≥300ms 或 ≥2 帧」，数字消失 340ms 即结束 |
| 3 | 只认 text/contentDescription | 自绘的跳过按钮（无文字）完全不可见 | 快照收录「可点击但无文字」的小控件 |
| 4 | 采了 `viewId` 却从没用过 | 最强的信号被浪费 | `skip/ad_close/splash_skip` 等 id 直接当强证据 |
| 5 | `跳过片头` 只扣 15 分，仍过阈值 | 每集开播都可能误点 | 显式排除，不再作为候选 |
| 6 | 点击时向上找 5 层可点击祖先 | 点到整屏的广告根容器，等于**打开广告落地页** | 最多 2 层，且祖先面积不得超过按钮 4 倍 / 屏幕 45% |
| 7 | 点击后无校验 | `ACTION_CLICK` 被 SDK 吃掉也算「完成」 | 0.4 秒后复查，按钮还在就补一次坐标点击 |
| 8 | 前台包名靠事件包名推断 | 系统弹窗一来就切走/再也回不来 | 每次轮询用 `getRootInActiveWindow().getPackageName()` 自己判断 |
| 9 | 节点不复用/不回收 | 高频扫描下 binder 节点池被耗尽，服务「悄悄失联」 | 不保留的节点立即回收 |
| 10 | `isAdWordHelper()` 是死代码 | 配置项从未生效 | 换成 `requireAdWord` 严格模式，默认关闭 |
| 11 | 倒计时结束一律上滑 | 红果会直接滑掉一整集 | 改为默认不上滑，新增「上滑继续」识别与可选开关 |

## 9. 已知限制

- 广告如果**完全没有节点**（纯 SurfaceView 自绘 + 对无障碍隐藏），读不到任何线索，属于技术上限；
  只能用第 6 节的兜底开关，代价是可能误滑。
- 强制观看型中插广告本身没有跳过按钮，工具只能等它自然结束，
  日志会写 `没找到跳过按钮，广告应该已自然结束`。
- 悬浮层形式的推广广告可能不响应上滑手势，此时只能等（日志会写 `连续上滑没滑走，暂停 12 秒再试`）。
- 无障碍服务需要进程常驻，被省电策略杀掉时去「电池 → 无限制」放行。
- 自动化操作可能违反某些应用的《用户协议》，请自行判断使用场景；本工具只在本机做辅助操作，
  不修改、不破解任何应用。

## 10. 自己编译

需要 JDK 17+、Android SDK（platform 34 / build-tools 34.0.0）。

```bash
./gradlew assembleRelease
# 本机只装了 build-tools 36 时，用 SDK 自带的 aapt2：
./gradlew assembleRelease -Pandroid.aapt2FromMavenOverride="$ANDROID_SDK/build-tools/36.0.0/aapt2.exe"
```

逻辑测试（纯 JVM，21 个用例）：

```bash
javac -encoding UTF-8 -d tools/out \
  app/src/main/java/com/autoskip/ad/{AdDetector,ScreenSnapshot,DetectorConfig}.java \
  tools/DetectorHarness.java
java -cp tools/out DetectorHarness
```
